# LatticeScholar 0.5 全面产品审计

> 历史说明：本文记录 0.5 当时的实现。v0.9 正式开源候选已把 PyMuPDF/Tesseract 改为显式可选高级引擎，默认核心改用 PDFPlumber + pypdf；许可与当前部署方式以 README 和 `THIRD_PARTY_NOTICES.md` 为准。

审计日期：2026-08-04  
审计对象：桌面/移动界面、PDF 解析、论文判断、证据链、安装发布、科研工作流与开源增长

## 一句话结论

0.4 已经具备“项目—检索—分析—期刊—政策—Idea—证据库”的完整骨架，但论文解剖仍存在一个 P0 信任缺口：系统没有告诉用户 PDF 读得是否正确，却直接给出看似完整的分析。0.5 的主线不是再增加生成按钮，而是先让“读对、说清、能回看”成立。

## 本轮已完成的 P0 / P1 改进

| 维度 | 原问题 | 0.5 处理 | 用户获得的变化 |
|---|---|---|---|
| 长文本 | 英文长标题突破证据卡片，局部省略规则不稳定 | 重构证据条目结构；全局 `min-width:0`、任意断行、三行钳制和悬停全文 | 标题、DOI、URL、项目名在桌面和手机均不越界 |
| PDF 阅读顺序 | 逐页字符串直接拼接，多栏、页眉页脚和断词错乱 | PyMuPDF 文本块 + 坐标排序 + 双栏识别；pypdf layout 兼容回退 | 阅读流更接近论文视觉版面 |
| 扫描件 | 只能提示用户先 OCR | 检测图片型页面；本机有 Tesseract 时按页 OCR，中英联合识别；Docker 默认提供 OCR | 常见扫描 PDF 可直接尝试解析，失败原因明确 |
| 提取可信度 | 用户不知道解析是否可靠 | 展示解析页数、字符数、语言、方法、质量分、正文结构、OCR 与截断状态 | 用户先判断“这次能不能信”，再看 AI 结论 |
| 中文一致性 | 零 Token 模式把英文原句当回答 | 中文解释模板与原文证据分离；模型输出做中文校验，不合格自动回退 | 英文论文也获得中文回答，原文引文仍不失真 |
| 科研判断 | 五段摘要层级平，实验充分性容易被一句结果替代 | 四问速读：痛点、创新增量、实验支撑、深挖清单；审慎结论标签 | 第一屏直接对应研究人员最关心的判断 |
| 长文成本 | 长 PDF 只截开头，Token 可能浪费在背景和参考文献 | 按摘要、方法、结果、讨论、结论、局限选择证据窗口 | 更低输入量覆盖更关键证据，避免只读开头 |
| 安装发布 | 包元数据段落错误，新打包工具无法安装 | 修正 PEP 621 元数据层级并重新执行 editable/wheel 安装 | GitHub 用户可按 README 安装 |
| 自动质量 | CI 没检查浏览器脚本语法 | Python 3.9/3.12 外增加 Node 22 静态检查；新增 PDF/API/中文回归测试 | 前端语法错误更难进入 Release |

## 科研人员端到端任务审计

### 1. 从问题到证据

现有项目容器、跨源检索、检索历史和题录导入已经能够完成日常查找，但还不能替代系统综述工具。当前适合“探索性检索、快速查新和课题证据积累”，不应宣称完成 PRISMA 流程。

下一阶段的进入门槛：必须先增加纳入/排除标准、双人筛选冲突、去重审计、排除理由和 PRISMA 数量日志，之后才能把“系统综述”写入产品能力。

### 2. 从单篇论文到可信判断

0.5 已补齐 PDF 读入健康度与四问速读。仍未解决的高价值问题是图表数字、公式语义、补充材料和跨论文矛盾。不能用通用文本模型假装已读懂图像表格。

下一阶段应先实现“主张—证据—样本—指标—限制”的本地证据矩阵，再做跨论文一致性与冲突提示；模型只负责候选归纳，用户负责确认每个单元格。

### 3. 从论文判断到选刊

现有期刊匹配基于相关论文发表样本，且明确不预测录用率，这是正确边界。仍缺少撤稿/更正状态、期刊官网文章类型、开放获取政策和用户机构协议等动态信息。

优先顺序应是：先接入 Crossmark/PubMed 等可追溯状态，再提供期刊官网核验清单；不把无法稳定授权的数据伪造成“实时影响因子”。

### 4. 从已有工作到新 Idea

Evidence Triad 已能把已有能力、文献和政策放在一起，但真正的新颖性仍需要跨源检索和反例寻找。下一阶段应增加“最强反例”“可证伪条件”“最低成本否证实验”和“与本人资源不匹配项”，而不是增加更多看似新颖的标题。

### 5. 从个人工具到长期科研记忆

项目、历史、笔记和导出构成了本地科研记忆的基础。高频缺口仍是 Zotero 双向同步、ORCID 成果导入、批量标签、阅读状态、团队批注和备份恢复。应优先使用官方 API 或文件互操作，不抓取受限页面。

## 可视化与体验审计

- 信息层级：四问作为首屏，详细拆解放入可展开层，降低长结果的阅读负担；
- 字体与触控：核心正文保持 12–15px，触控按钮有明确面积，移动端从双栏切为单栏；
- 失败反馈：区分文件损坏、加密、无文字、OCR 缺失、提取质量低、模型回退和截断；
- 可访问性：保留语义 `section/article/details/summary`、键盘快捷键和 `aria-live` 文件状态；
- 认知安全：不用绿色“通过”表示论文正确，只表示“文本中出现了较完整的支撑信号”；
- 隐私：上传 PDF 仅在内存处理，不保存全文；远程模型仍需用户显式允许。

## 资源预算

| 路径 | 计算/网络 | Token | 适用场景 |
|---|---|---:|---|
| 规则中文分析 | 本机 CPU，毫秒至秒级 | 0 | 快速筛读、隐私材料 |
| 文字型 PDF | 本机文本块提取 | 0 | 绝大多数电子论文 |
| 扫描 PDF OCR | 本机 CPU，按扫描页增加延迟 | 0 | 图片型老文献、扫描报告 |
| 本地 Ollama | 本机模型算力 | 取决于本地模型 | 深度归纳且不外发 |
| 远程兼容模型 | 网络 + 商业模型 | 证据窗口后的输入/输出 | 用户明确同意的深度分析 |

## 后续优先级（没有伪装成已完成）

1. P0：真实用户 PDF 失败样本回归库；只保存用户获准分享或合成的最小复现文件；
2. P0：主张—证据矩阵与跨论文冲突提示；
3. P0：撤稿、更正、版本与 PMID/DOI 状态核验；
4. P1：系统综述筛选、排除理由与 PRISMA 审计；
5. P1：Zotero 官方接口/插件与 ORCID 导入；
6. P1：阅读队列、批量标签、备份恢复和可迁移项目包；
7. P2：团队空间、角色权限、批注与审阅；
8. P2：图表/表格结构化解析，前提是能显示数字来源与失败质量。

## 开源高星不是功能堆积

发布后最重要的增长资产是：三分钟可运行、真实演示、明确边界、快速修复、可复现 Issue 和稳定 Release。仓库应在首发前准备一段 60–90 秒 GIF、三张无版权演示图、一份合成 PDF、`good first issue` 列表和公开路线图。星标是用户对持续价值的结果，不能由 README 文案保证。
