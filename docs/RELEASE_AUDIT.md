# v0.9.0 开源发布审计报告

审计日期：2026-08-04  
审计对象：LatticeScholar v0.9.0 GitHub 源码发布包  
结论：在执行本报告列出的发布命令、使用白名单归档且不加入本地运行数据的前提下，可作为首个公开候选版本。

## 1. 公开范围

源码包采用 `OPEN_SOURCE_MANIFEST.txt` 白名单，只包含：应用源码、静态页面、测试、公开文档、示例配置、容器配置和 GitHub 协作配置。不会包含本地数据库、账号、邮件验证码、模型密钥、检索缓存、加密材料、测试覆盖率数据库、构建产物或宣传视频。

## 2. 敏感信息审计

已检查常见私钥头、GitHub Token、OpenAI 风格密钥、AWS Access Key 和生产环境文件。公开文件中只保留显式占位符。以下路径被强制排除：

- `.env`：真实环境变量；
- `.data/`：SQLite、会话秘密、BYOK 加密材料、缓存和日志；
- `.git/`：本地历史和远端信息；
- `.venv/`：本机依赖；
- `release/`、`promotion-kit/`、`dist/`、`build/`：生成文件；
- 覆盖率、测试、解释器和编辑器缓存。

发布前仍须再次运行密钥扫描，因为用户可能在审计后新增文件。即使密钥已从当前文件删除，只要曾被提交到 Git 历史中，也必须先撤销并轮换该密钥，再清理历史。

## 3. 许可证审计

- 项目源码：Apache License 2.0；
- 默认 PDF 栈：PDFPlumber + pypdf，不默认加载 AGPL 组件；
- 可选 `advanced-pdf`：PyMuPDF/PyMuPDF4LLM，采用 AGPL v3 或 Artifex 商业许可；
- 依赖不随源码压缩包再分发，安装时从上游取得；
- 具体列表、风险与上游入口见 `THIRD_PARTY_NOTICES.md`。

本轮已将高级 PDF 引擎从默认安装移出，避免用户在不知情时把双许可组件当作 Apache-2.0 核心的一部分。商业或公网部署可选引擎前仍需单独评估。

## 4. 产品与合规边界

- 不绕过知网、Google Scholar、Web of Science 等平台的登录、订阅、验证码或反爬限制；
- 自动政策发现只产生候选，发布前仍需人工核验官方链接、发布日期与效力；
- 期刊匹配不预测录用率，不虚构影响因子、分区或审稿周期；
- PDF 解读和模型回答不保证绝对准确，证据页码、数值、公式、表格和补充材料必须回原文复核；
- BYOK 密钥不回显，但公开部署仍应配置 TLS、稳定加密密钥、秘密管理器、访问控制和备份。

## 5. 工程质量门槛

正式归档前执行：

```bash
ruff check src tests
python -m compileall -q src
node --check src/latticescholar/static/app.js
pytest --cov=latticescholar --cov-report=term-missing --cov-fail-under=85
python -m build
```

通过标准：所有自动化测试通过、总代码覆盖率不低于 85%、源码包和 wheel 均能构建、公开归档重新扫描无密钥命中。浏览器端至少复核桌面与移动端的总览、检索、PDF、Idea Lab、模型控制台和登录流程。

## 6. 发布后不能忽略的事项

1. 为 `main` 设置分支保护，要求 CI 通过后才能合并；
2. 开启 Dependabot、Secret scanning、Push protection 与私密漏洞报告；
3. 使用 Issue 模板收集可复现输入，PDF 报告应提醒用户先脱敏；
4. 每次发布重新核对依赖许可证、数据源条款和政策源；
5. 发现泄露密钥时，先轮换密钥，再处理仓库历史；
6. 不把测试覆盖率、星数、模型输出或检索数量宣传成科研结论准确率。

## 7. 尚存风险

- 没有自动测试能证明任意 PDF 都能被准确解析；扫描件、多栏、公式和复杂表格仍有边界；
- 第三方 API、模型、数据源字段和价格会变化；
- 本报告是工程发布审计，不是法律、科研伦理或数据保护意见；
- 首次公开前，建议由项目所有者逐项确认作者身份、商标、示例数据来源和所在单位的成果管理要求。
