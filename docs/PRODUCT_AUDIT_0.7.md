# 产品审计 0.7：让模型成为科研工作流，而不是另一个聊天框

## 结论先行

本轮最重要的产品判断是：接入 DeepSeek 本身不会让项目变成高质量科研平台。只有当模型理解当前课题、受真实证据约束、输出可核验结构、成本可见、隐私边界清楚时，它才比直接打开通用 AI 多出不可替代的价值。

0.7 已形成三条差异化链路：

1. 中文研究问题 → DeepSeek 生成可编辑的中英文检索式 → 多源检索与去重 → 检索条件自动留痕；
2. PDF 本地解析 → 有页码的证据窗口 → Pro 模型固定中文四问回答 → 原文复核与项目归档；
3. 项目研究问题 + 私有证据库 + 已选政策 → 证据约束研讨 → 不确定性与本周交付物 → 保存回项目。

## 此前缺口

### 模型体验

- 只有通用 provider 配置，用户不知道 DeepSeek 应选哪个模型；
- 短检索任务和长文推理使用同一路线，时间与成本不可控；
- 页面只显示“模型已启用”，没有调用、Token、缓存和耗时反馈；
- 没有连接自检、DeepSeek 专属错误说明或偶发空 JSON 重试；
- 模型结果与科研项目、证据库之间联系较弱。

### 科研交流

- 任务台解决个人推进，但项目中缺少结构化“讨论—判断—行动”闭环；
- 直接做公共论坛会立即面对身份冒充、抄袭、泄密、骚扰、错误建议和版权问题；
- 通用聊天记录难以沉淀为课题资产，也无法说明回答引用了哪些内部证据。

### 可维护性

- 模型用量无法按用户审计，托管服务难以定价或发现异常；
- Key 配置说明不足，容易诱导用户在浏览器或 Issue 中泄漏密钥；
- 新增模型代码会稀释覆盖率，却没有对应的协议测试。

## 已完成改造

### DeepSeek 原生适配

- 使用官方 OpenAI 兼容 Chat Completion 路径和 JSON Output；
- 默认模型更新为 `deepseek-v4-flash` 与 `deepseek-v4-pro`；
- `balanced`、`economy`、`quality` 三种可解释路由；
- 论文、Idea、研讨自适应启用 thinking，检索式和连接测试关闭 thinking；
- 支持 `reasoning_effort`、有限重试、超时、空响应和主要 HTTP 错误的中文提示；
- 用内部数字 ID 构造非个人化 `user_id`，不把邮箱交给模型；
- 记录输入、输出、缓存命中/未命中、推理 Token、耗时、任务与模型，不记录内容。

### 文献雷达

- 新增“生成双语检索式”，保留用户人工编辑权；
- 输出中文概念、英文术语、排除项和检索解释；
- 明确它只生成检索策略，不生成论文、DOI、作者或结果；
- 生成后仍走原有多源检索、筛选、去重和项目留痕，而不是让模型凭记忆回答。

### 科研研讨室

- 五类任务：研究问题、文献缺口、实验设计、组会反馈、写作结构；
- 必须绑定当前科研项目，避免无上下文对话；
- 可选当前项目证据和已选政策，证据限制为最多 12 条有限字段；
- 模型只能引用真实 `E<编号>`，虚构引用自动剔除；
- 输出固定为直接结论、3—6 条判断、证据编号、不确定性和本周行动；
- 结果可以保存到当前项目证据库，形成可回看的讨论记录。

### 模型中心

- 可视化配置状态、远程发送授权、路由、thinking 和任务—模型映射；
- 一键最小连接测试；
- 近 30 天用量和最近 12 次任务元数据；
- 服务器端配置示例、官方文档与定价入口、敏感数据分级提示；
- 无配置时明确引导，不让用户在页面输入或保存平台所有者的 Key。

## 为什么比检索网站和通用 AI 更有价值

| 用户任务 | 单一检索网站 | 通用 AI | LatticeScholar 0.7 |
|---|---|---|---|
| 找论文 | 单库检索强，但需跨站搬运 | 可能遗漏或虚构来源 | 先生成双语策略，再从真实来源检索、去重并留痕 |
| 读论文 | 原文完整，提炼靠人工 | 总结快，但证据位置容易丢 | 本地解析、四问中文回答、页码依据和质量诊断 |
| 找缺口 | 需要长期比较 | 容易把“没看到”说成“首次” | 只基于项目证据讨论，并显式列出不确定性和补检动作 |
| 做组会 | 手工整理 | 对话难沉淀 | 项目化研讨，判断和任务可保存为证据记录 |
| 控制成本 | 无模型成本 | 用量通常与科研任务脱节 | 按任务选模型，展示 Token、缓存和耗时 |

## 仍然不足，不能对外夸大

### P0：发布前必须继续守住

- DeepSeek、学术源和政策源都可能变化；需要版本兼容测试和清楚的降级路径；
- 复杂公式、图片实验图和跨页表格还不能保证准确解析；
- “当前项目证据不足”必须保持为正常答案，不能为了体验强行生成结论；
- 托管环境需要服务器队列、速率限制、预算告警、密钥轮换和供应商账单对账；
- 真实 API 端到端测试只能使用公开样例，不得把用户敏感论文纳入 CI。

### P1：下一阶段最有用户价值

- PRISMA 风格系统综述工作流：纳入排除标准、双人筛选、冲突处理和流程图；
- 证据矩阵：研究对象、数据规模、方法、基线、指标、结论、局限的可编辑表格；
- 引用上下文核验：区分支持、反驳和背景引用，检查正文是否真的支持陈述；
- 实验账本：环境、数据版本、随机种子、超参数、失败记录与结果文件哈希；
- 组会包导出：一页结论、证据编号、未决问题和下周任务；
- Zotero 双向同步，但必须通过官方接口或用户授权，不绕过数据库条款。

### P2：公共科研交流平台

不建议现在直接上线无审核社区。正式跨用户交流至少需要：

- 高校或机构身份可选验证，同时允许合理匿名；
- 发帖前敏感信息和版权提醒、可撤回与彻底删除；
- 结构化问题模板、可复现材料声明和利益冲突披露；
- 举报、审核、封禁、申诉、反骚扰和学术不端处理；
- 私信权限、速率限制、垃圾信息治理与未成年人保护；
- 回答不能被点赞数自动标记为“正确”，应突出证据和可复现性。

0.7 的科研研讨室是安全的第一步：先让高质量讨论格式在个人项目中成立，再把脱敏后的“研究问题 + 已尝试 + 证据包 + 具体阻塞”导出到未来社区。

## 高星开源项目的现实策略

星标无法通过界面或模型名称保证。更可持续的增长来自：

1. README 在一分钟内展示清楚的科研闭环、截图和可运行示例；
2. 首次启动不强制模型或商业 Key，基础工作流真正可用；
3. 用公开论文提供可复现 Demo，展示从检索到研讨的完整结果；
4. 每个 Issue 有复现模板、隐私提示和明确维护响应；
5. 小步发布、清楚 Changelog、迁移指南和稳定测试；
6. 不用“准确无误”“保证创新”“预测录用”等无法证明的宣传语；
7. 将学生真实交付物——证据表、复现记录、组会包——作为核心产出，而不是增加更多聊天入口。
