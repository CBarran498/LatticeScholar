# 产品分析与路线图

## 1. 目标用户与高频痛点

### 高校教师 / PI

- 前沿跟踪碎片化，难以把领域进展、团队能力、国家任务和可转化场景同时纳入决策；
- 论文、项目、学生指导、报销和行政任务争夺时间；
- “热点”与“真正能做、值得做、能形成理论贡献”的方向难以区分；
- 合作对象、数据、设备、伦理、知识产权和项目周期往往比算法本身更早成为瓶颈。

### 青年教师 / 博士后

- 需要在有限算力、数据和团队规模下找到独立研究标签；
- 既要追求前沿，又要考虑基金窗口、成果周期和职称评价；
- 缺少可解释的期刊选择依据与拒稿后的系统复盘；
- 对统计功效、复现、开放科学和科研伦理支持不足。

### 研究生

- 不知道如何把宽泛主题拆成可复现检索式与证据矩阵；
- 容易把论文摘要中的宣传性表述当成已证明创新；
- 文献笔记、引用、代码、数据和实验记录相互脱节；
- 生成式 AI 可能引入伪引文、不可追溯改写和学术诚信风险。

### 科研管理人员

- 政策信号、项目指南、团队成果和学科能力缺少统一语义；
- 项目查重、风险、伦理、数据与知识产权审查缺少前置工具；
- 汇报口径容易只看论文数和引用数，忽视证据质量与社会影响。

## 2. 产品决策

| 决策 | 原因 | 当前实现 |
|---|---|---|
| 隐私优先 | 未公开想法、PDF 和实验信息敏感 | 本地开源部署、邮箱账号隔离、PDF 不落盘、远程 LLM 显式同意 |
| 元数据优先 | 全文版权、付费墙和接口稳定性 | 正规学术元数据源，不绕过访问控制 |
| 证据链优先 | AI 总结最危险的是“说得像真的” | DOI、来源、日期、片段、缺失提示 |
| 零 Token 基线 | 普通办公电脑也要能用 | 规则抽取、词汇匹配、模板化假设 |
| 可解释分数 | 单一黑盒分数会放大偏差 | 分开展示主题、样本量、时效、引用信号 |
| 不承诺结果 | 录用率、新颖性和立项成功不可可靠预测 | 明确 caveat 与人工核验清单 |

## 3. 端到端工作流

1. 创建科研项目，把研究目标表达为“对象 + 方法 + 场景/约束”；
2. 多源检索，查看来源故障、元数据缺失与重复合并，并保存可复现条件；
3. 选择关键论文，抽取问题、方法、创新声明、发现和局限；
4. 用真实发表样本反推候选期刊，并到官网核验；
5. 按主题检索官方政策，选取确实相关的战略信号；
6. 录入团队已经验证的能力，形成三个可证伪方向；
7. 用首轮实验、反证、伦理与资源约束淘汰弱 Idea；
8. 导出 Markdown 研究简报或 BibTeX/RIS 题录，进入文献管理、系统查新或预注册。

## 4. 高质量开源产品与托管服务的护城河

LatticeScholar 的可持续差异化应来自：

- **可信 UX**：对不确定性、缺失与来源故障做一等展示；
- **轻量可用**：不配模型也有完整基础价值，自托管只需普通 CPU 服务器；
- **可扩展数据源**：统一 Paper/Policy schema 与来源适配器；
- **内部评测**：用人工标注集衡量检索去重、证据抽取与幻觉率；
- **学科包**：医学、工程、人文社科分别配置术语、伦理与数据源；
- **可维护扩展面**：数据源适配器、解析器、翻译和可访问性改进都可独立迭代。

收入不依赖锁住社区代码，而来自官方托管的免部署体验、模型与数据源成本管理、同步协作、可靠性和支持。Free 必须能独立完成基础任务；Pro 集中承载有持续边际成本的能力。详见 [商业化设计](MONETIZATION.md)。

## 5. 后续能力边界

优先级按“可信价值 / 实现与维护成本”排序：

1. 撤稿、更正、开放获取与论文版本检查；
2. Zotero 和 ORCID 双向互操作；
3. 可复现系统综述与 PRISMA；
4. 本地语义索引和跨论文矛盾检测；
5. 项目申请书证据审计，而不是代写；
6. 实验记录、数据管理计划、统计功效与伦理预检；
7. 团队协作、权限与机构级部署。

“自动投稿”“自动生成创新点”“保证高水平论文/基金命中”不进入路线图。
