# 产品审计 0.6：从功能集合到研究工作流

> 历史说明：本文记录 0.6 当时的实现。v0.9 正式开源候选已把 PyMuPDF/Tesseract 改为显式可选高级引擎，默认核心改用 PDFPlumber + pypdf；许可与当前部署方式以 README 和 `THIRD_PARTY_NOTICES.md` 为准。

## 审计结论

此前版本具备多源检索、论文分析、期刊匹配、政策和 Idea 等模块，但存在三个结构性问题：页面信息层级偏密、英文口号和模板化表达过多；文献结果没有把“可解读摘要”和“仅题录记录”分层；PDF 版面提取与中文语义分析的能力边界表达不够清楚。

0.6 的产品原则是：围绕课题保留可复查过程，而不是增加另一个通用聊天界面。

## 本轮改造

- 重新设计字体、间距、色彩、卡片层级、导航、动效和移动端布局；
- 用科研任务语言替换主要页面中的营销式、AI 式文案；
- 增加中文主题与英文检索式双输入；
- 增加语言、摘要、开放获取、年份、最低引用信号和排序筛选；
- 中文、English、中英混合、有摘要结果独立分组；
- 不再为每条缺摘要结果重复渲染长警告，改为“仅题录”状态与合法获取原文动作；
- 排序加入资料完整度信号，同时保留引用量不等于质量的提醒；
- PDF 优先使用 PyMuPDF4LLM 的 Markdown、多栏和分页阅读流，低文字量时回退 OCR；
- 中文解读继续强制使用中文说明，原文引文保留原语言和页码；
- 新增使用指南、检索帮助、PDF 能力说明、实验充分性与复现清单；
- 新增科研任务台，用本周交付物帮助学生建立可检查进度；
- 明确公开科研社区的治理前置条件，不在缺少审核和隐私机制时上线无约束论坛；
- 将测试覆盖率硬门槛提升到 85%。

## 与检索网站和通用 AI 的区别

检索网站擅长发现单条记录，通用 AI 擅长临时对话；LatticeScholar 的差异应体现在：同一个课题上下文、中英文可复现检索式、多源合并去重、页码证据、决策记录、个人证据库和下一步任务。

## 仍需继续建设

- Crossref、OpenAlex 等来源的摘要覆盖和限流无法由本项目单方面消除；
- 自动中英检索式扩展需要可审计的术语表或模型配置，不能静默翻译；
- 复杂公式、图像和无规则表格仍需专门的视觉模型或人工复核；
- 社区功能需要机构身份、审核、举报、封禁、数据删除、版权和学术诚信规则；
- 期刊 APC、收录与政策有效性必须从官方源持续核验。
