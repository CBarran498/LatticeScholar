## 结论

LatticeScholar 0.9.0 已完成代码质量、自动化测试、源码包/wheel 打包、PDF 版面解析、固定中文分析和浏览器端到端验证。本轮特别验证了多格式已有工作导入、压缩包安全上限、Idea Lab 合并上下文、中文孤行检查、动态研究证据引擎、暗色主题和响应式布局。

## 0.6 PDF 与中文分析专项验证

- 用 PyMuPDF 在内存中生成三页合成学术 PDF，覆盖重复页眉页脚、英文断词、双栏方法/结果、讨论与结论；
- 解析结果正确保留 `第 1/2/3 页` 锚点，去除重复页眉，修复 `multi-\nmodal`，识别摘要、方法、结果、讨论和结论；
- 英文输入的核心问题、方法、创新、结果、局限、四问判断和提醒均含中文解释，直接引文保持英文；
- “缺少外部验证 / 外部验证仍是未来工作”不会因为命中关键词而被计作实验支持，结果正确标记为“部分支持”，并把统计检验、外部验证列入待核验项；
- 损坏 PDF 返回 422 与中文错误原因；扫描页在 Tesseract 不可用时给出明确安装/替代路径；
- 当前 macOS 主机未安装 Tesseract，因此没有伪造本机 OCR 成功记录；Dockerfile 已声明 `tesseract-ocr` 与简体中文语言包，但当前主机没有 Docker 命令，容器镜像尚未在本机实际构建。

以上为 0.6 历史记录；正式发布候选已将 PyMuPDF/Tesseract 移到显式可选高级引擎，Docker 核心镜像不再默认安装。

## 0.9 开源发布候选复验

- 默认环境 `LATTICE_PDF_ENGINE=core`，PDFPlumber 版面提取失败时由 pypdf 兜底；
- 测试 PDF 由 BSD 许可的 ReportLab 在内存中生成，不再依赖 PyMuPDF 生成测试样本；
- PyMuPDF 与 PyMuPDF4LLM 只存在于 `advanced-pdf` 可选依赖，并通过环境变量显式启用；
- 公开归档使用白名单构建，排除 `.env`、`.data/`、`.venv/`、Git 历史、缓存、宣传素材和构建目录；
- 发布候选必须重新通过 85% 覆盖率门槛、前端语法检查、源码构建和敏感信息扫描。
